# Riesgos y limites de la auditoria

## Riesgos vigentes

- Sin navegador autenticado contra Emulator no se puede evidenciar visualmente que cada
  control sea operable ni que el callable remoto acepte la publicacion.
- La matriz se apoya en especificacion FMCH y rutas de codigo; los significados
  deportivos ambiguos requieren dictamen de jueces, no inferencia tecnica.
- El id duplicado ttm merece correccion controlada antes de certificar auditoria por
  concepto de Toro.
- Una cuarta fila de Coleadero no debe agregarse como parche de formato porque afecta
  modelo, roster, score, historial y exportacion.
- La hoja actual es una proyeccion funcional, no una reproduccion completa del documento
  FMCH con firmas, marcas institucionales y pie.

## Riesgos mitigados por esta auditoria

- Se evita clasificar como faltantes metros, punta, oportunidades, reglas aplicadas,
  malos o totales que ya existen bajo una representacion distinta.
- Se separan huecos de captura/calculo de huecos de formato y de transformacion.
- No se introdujo ningun cambio funcional mientras no exista validacion local completa.

## Condicion para cerrar el riesgo

Configurar runtime de navegador para Emulator, ejecutar las diez pantallas con fixture
autorizado y volver a producir la evidencia visual, persistida y de callable oficial.
